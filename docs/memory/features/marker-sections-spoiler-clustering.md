# Marker sections split · spoiler coverage · vmap clustering toggle

Three UX changes landed 2026-07-23 (user asks 1–5). Current-code truth below.

## 1 · Three display sections (was: one "World")

The old crowded **World** section was split into three, entirely **data-driven** via the `section`
field in `data/categories.json` → regenerated by `tools/generate_categories.py` into
`CATEGORY_META[].section`. `section_of()` (`goblin_section_visibility.cpp`) reads that string via
`section_from_name()`.

- **World** — collectibles: Maps, Paintings, Imp Statues, Kindling Spirits, Interactables.
- **POI** — discovery landmarks: Churches, Ruins, Forts, Castles, Towns, Colosseums, Dungeons,
  Legacy Dungeons, Divine Towers, Rises & Towers, Evergaols, Minor Erdtrees, Miquella's Cross,
  Shacks, Unique Sites, Portals, Stakes of Marika, Spirit Springs, Spiritspring Hawks, **Bosses**,
  **Hostile NPC**, **Quest NPC**.
- **Services** — functional: Graces, Merchants, Elevators, Grand Lifts, Smithing Tables, Summoning Pools.

Wiring for a new section (all done): `enum class Section` (+ `section_name` / `section_from_name`),
`sectionPOI`/`sectionServices` config bools (`goblin_config.hpp` extern + `goblin_config_schema.cpp`
definition + INI keys `section_poi`/`section_services`), and the `sec_cfg[]` seed + `persist_settings()`
write-back indices (7 = POI, 8 = Services). The F1 panel is fully `section_count()`-driven → auto.
The classification is data only — re-tag rows in `categories.json` + regen to move a category.

## 2 · Spoiler-free (`anonymousLoot`) — single predicate, wider coverage

SSOT predicate = `goblin::worldmap::marker_is_anonymized(m)` (`map_renderer.hpp/.cpp`) =
`cfg_anonymousLoot && anonymous_marker(m)`. `anonymousLoot` = master on/off; **`anonymousLootAggressive`**
= level (config bool, INI `anonymous_loot_aggressive`, default **false** = light; radio in F1 settings).

`anonymous_marker()` is **two-level** (user 2026-07-23):

- **LIGHT** (default): `m.lot_backed || category == WorldFarmableCollectible` — only markers whose
  identity is randomized (treasure/enemy drops + farmables). Bosses, rune/ember pieces, material nodes,
  kindling and landmarks KEEP their names.
- **AGGRESSIVE "blackout"**: `!m.discover_flag` — EVERY marker except graces → "?" (`discover_flag` is
  grace-only; graces stay named/warpable). Positions only; for a blind randomizer run.
- Bosses stay distinguishable in aggressive: `draw_marker`'s anon branch draws a **bigger, red-tinted
  "?" disc** for `anonymous_is_boss(m)` (WorldBosses), neutral gray "?" for everything else.
- **Virtual-map tooltip fix (ask 2):** the vmap builds its OWN tooltip (`panel_virtual_map.cpp` ~2090)
  and used to bypass the spoiler check → leaked the real name on hover. Now it captures
  `hoverAnon = marker_is_anonymized(*m)` at each hover site and shows "?" (name + category line both
  hidden — the category can itself be the identity, e.g. "Rune Pieces"). Graces are never anonymized.

## 3 · vmap clustering now obeys the manual toggle (ask 3)

The Virtual World Map had an **always-on zoom-LOD** cluster (`clusterWorld = kPilePx / zoom`) that
ignored the `enableClustering` toggle + `clusterThreshold` (those only drove the native worldmap).
Now (`panel_virtual_map.cpp` ~1862): `enableClustering` OFF → `clusterWorld = -1` disables the
quadtree collapse test (every marker individual at any zoom); ON → zoom pile size but a node only
piles once it holds ≥ `clusterThreshold` markers. `MarkerQuadtree::query/collect` gained a `minCount`
param (`marker_quadtree.hpp`).

**Known gap / follow-up:** per-category `clusterExclude` and `clusterDistanceAdaptive` are NOT yet
honored on the vmap (position-only quadtree; native map only). `enableClustering` defaults **false**,
so the vmap now shows all markers individually until grouping is turned on.
